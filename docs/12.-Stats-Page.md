## Server statistics

TabbyAPI counts what it does and can show it at `http://<host>:<port>/stats`: live activity, counters for this run, and counters kept across every run.

The page reads `GET /v1/stats`, which needs an API key (the admin key also works). The page itself holds no secrets and asks for a key the first time, exactly like the [chat client](03.-Usage.md#chat-client); if the browser has already used the chat client, the key is already there. The server prints the page's address at startup.

### What it shows

- **Now** — generation rate, jobs in flight and what stage they are at, KV cache usage (with cache hit rate and the system memory and disk tiers when the engine has them), and VRAM per GPU.
- **Counts** — tokens generated, prompt tokens, how much of the prompt had to be processed and how much came from cache, generation and prompt rates, the median and 95th percentile generation rate of this session, average time to first token, request counts, draft acceptance, embeddings, and why generations finished. Counters are side by side for **this run** and **all time**.
- **History** — tokens generated per hour (the last 48 hours) and per day (the last 14 days).
- **Models** — requests, tokens and load counts per model, over every session.
- **Errors** — the same issues `/health` reports, when there are any.

Blocks hide themselves when they have nothing to report: with no model loaded there is no cache or job list, with no draft model there is no draft row, and on a fresh install there is no history.

### Where the numbers live

Counters are kept in `logs/stats.json`, written atomically every 60 seconds while there are changes and once more at shutdown. Delete the file to start over; if it can't be read, counting starts fresh and the server logs a warning instead of failing to boot.

| Setting | Default | Meaning |
| --- | --- | --- |
| `network.stats_page` | `true` | Serve the page at `/stats`. `/v1/stats` is always available. |

Two details worth knowing:

- Live cache and VRAM figures are best effort. A backend that doesn't report cache statistics shows no cache block, and a GPU whose memory can't be read shows no VRAM block. Counters are unaffected.
- Generator rate percentiles are computed from this session's requests. Older samples are not persisted, because a percentile over an arbitrary slice of history says less than the average, which is exact.
